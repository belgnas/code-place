## 1. 什么是 Markdown

Markdown 是一种**轻量级标记语言**，由 John Gruber 于 2004 年创建。它的设计目标是让人们使用**纯文本**编写文档，同时保持可读性，并能轻松转换为 HTML。

### 核心特点

| 特点 | 说明 |
| --- | --- |
| 纯文本 | 用任何文本编辑器都能编写，文件后缀 `.md` 或 `.markdown` |
| 易读易写 | 语法简洁，即使不渲染也具有良好的可读性 |
| 广泛支持 | GitHub、VS Code、Notion、Typora 等主流工具都支持 |
| 版本控制友好 | 纯文本格式，方便 Git 追踪变更和对比差异 |

### 常见用途

- 项目文档（README.md）
- 技术博客
- 笔记与教程
- 算法题解
- API 文档

## 2. 标题

### 语法

使用 `#` 号开头，后跟一个空格，然后写标题文字。`#` 的数量对应标题级别（1~6 级）。

### 写法

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

### 替代写法

一级和二级标题也支持用 `=` 和 `-` 在下一行划线：

```markdown
一级标题
=======

二级标题
-------
```

> 这种方式不常用，建议统一使用 `#` 语法以保持一致性和可读性。

### 注意事项

- `#` 与标题文字之间必须有一个空格（部分解析器会容错，但不规范）
- 建议在标题前后的空行，使文档结构更清晰
- 一级标题通常一个文档只使用一次（作为文档标题）

## 3. 文本样式

### 3.1 加粗

```markdown
**加粗文字**
__加粗文字（替代写法）__
```

**效果**：**加粗文字**

> 推荐使用 `**`，因为 `__` 在某些上下文中容易与变量名中的下划线混淆。

### 3.2 斜体

```markdown
*斜体文字*
_斜体文字（替代写法）_
```

**效果**：*斜体文字*

### 3.3 加粗斜体

```markdown
***加粗斜体***
**_加粗斜体（混合写法）_**
```

**效果**：***加粗斜体***

### 3.4 删除线

```markdown
~~删除的文字~~
```

**效果**：~~删除的文字~~

### 3.5 行内代码

```markdown
使用 `printf()` 函数输出
```

**效果**：使用 `printf()` 函数输出

> 行内代码中的内容不会被当作 Markdown 语法解析。

### 3.6 高亮（部分平台支持）

```markdown
==高亮文字==
```

**效果**：==高亮文字==

> ⚠️ **注意**：高亮语法并非标准 Markdown，仅在 Typora、Obsidian、GitHub 等特定平台支持。

### 3.7 上标与下标（部分平台支持）

```markdown
H~2~O         → 水分子（下标）
E = mc^2^     → 质能方程（上标）
```

**效果**：H~2~O / E = mc^2^

> ⚠️ **注意**：上下标也不是标准 Markdown 语法，GitHub Flavored Markdown 不支持。在 GitHub 上推荐使用 `<sub>` 和 `<sup>` HTML 标签替代。

## 4. 段落与换行

### 4.1 段落

段落之间用**空行**分隔。

```markdown
这是第一个段落。

这是第二个段落。
```

### 4.2 软换行

在行尾加**两个空格**再回车，新行仍属于同一段落。

```markdown
第一行··
第二行（同一段落）
```

> 这里 `··` 表示两个不可见的空格。

### 4.3 硬换行

使用反斜杠 `\` 再回车，或直接空行。

```markdown
第一行\
第二行（硬换行）
```

### 注意事项

- 大多数 Markdown 编辑器中，单纯按一次回车不会产生新行（这和 Word 不同）
- 建议使用空行分隔段落，保持源码的可读性
- 软换行中的两个空格容易被编辑器清除，不够可靠，推荐使用硬换行或空行分段

## 5. 列表

### 5.1 无序列表

使用 `-`、`*` 或 `+` 作为列表标记，推荐统一使用 `-`。

```markdown
- 项目一
- 项目二
- 项目三
```

**效果：**
- 项目一
- 项目二
- 项目三

### 5.2 有序列表

使用数字 + 英文句点 + 空格。

```markdown
1. 第一步
2. 第二步
3. 第三步
```

**效果：**
1. 第一步
2. 第二步
3. 第三步

> 数字可以不连续，Markdown 会自动按顺序渲染。但为了源码可读性，建议保持连续。

### 5.3 嵌套列表

子列表前缩进**两个或四个空格**。

```markdown
- 一级项目
  - 二级项目
    - 三级项目
  - 另一个二级项目
```

**效果：**
- 一级项目
  - 二级项目
    - 三级项目
  - 另一个二级项目

### 5.4 有序与无序列表混合

```markdown
1. 第一步
   - 选项 A
   - 选项 B
2. 第二步
   - 选项 C
```

### 5.5 列表中的多段内容

```markdown
1. 第一个项目。

   这是第一个项目的细节说明（缩进对齐）。

2. 第二个项目。

   ```cpp
   // 代码块也要缩进对齐
   cout << "Hello";
   ```
```

### 注意事项

- 列表标记与内容之间必须有空格
- 嵌套时缩进必须一致，混用 tab 和空格会导致渲染异常
- 列表后如果要放代码块，代码块需要缩进对齐列表文字

## 6. 链接

### 6.1 行内式链接

```markdown
[链接文字](URL "可选的标题")
```

```markdown
[GitHub](https://github.com "点击访问 GitHub")
```

**效果**：[GitHub](https://github.com "点击访问 GitHub")

> 标题（title）是可选的，鼠标悬停时显示。

### 6.2 参考式链接

将 URL 统一放在文档末尾，正文中更简洁。

```markdown
本文参考了 [GitHub 文档][gh] 和 [CommonMark 规范][cm]。

[gh]: https://docs.github.com
[cm]: https://commonmark.org
```

> 参考式链接适合**同一 URL 多次出现**的场景，便于集中管理和维护。

### 6.3 自动链接

用尖括号包裹 URL 或邮箱地址。

```markdown
<https://www.google.com>
<user@example.com>
```

**效果**：<https://www.google.com>

### 6.4 锚点链接（页内跳转）

```markdown
[跳转到标题部分](#2-标题)
[回到目录](#📑-目录)
```

> 锚点 ID 通常是标题文字的小写，空格替换为 `-`，去掉标点。中文标题的锚点在 GitHub 上会保留中文（URL 编码）。

## 7. 图片

### 7.1 基本语法

```markdown
![替代文字](图片URL "可选标题")
```

```markdown
![C++ Logo](https://example.com/cpp-logo.png "C++ 编程语言")
```

### 7.2 带链接的图片

```markdown
[![替代文字](图片URL)](链接URL)
```

```markdown
[![GitHub](https://example.com/github.png)](https://github.com)
```

### 7.3 无法显示图片时的替代方案

- 正确填写 `替代文字`（alt text），在图片加载失败时会显示
- 替代文字对无障碍访问（屏幕阅读器）也很重要

### 7.4 控制图片大小（HTML 方式）

Markdown 原生不支持调整图片大小，需要借助 HTML：

```html
<img src="图片URL" width="300" alt="描述" />
<img src="图片URL" style="width:50%" alt="描述" />
```

### 注意事项

- 图片 URL 不能有空格，否则会被截断
- 本地图片可使用相对路径：`![logo](./images/logo.png)`
- GitHub 上的图片在 README 中推荐使用**仓库内的相对路径**，而不是本地绝对路径

## 8. 代码

### 8.1 行内代码

用一个反引号包裹：

```markdown
使用 `std::sort()` 进行排序。
```

**效果**：使用 `std::sort()` 进行排序。

### 8.2 代码中的反引号

如果代码中本身就包含反引号，用**两个反引号**包裹：

```markdown
`` 这个 ` 是代码的一部分 ``
```

### 8.3 围栏代码块

使用三个反引号 ` ``` ` 包裹，可在开头指定语言：

````markdown
```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "Hello, World!" << endl;
    return 0;
}
```
````

### 8.4 支持的语言标识

| 语言 | 标识 |
| --- | --- |
| C++ | `cpp`, `c++` |
| C | `c` |
| Java | `java` |
| Python | `python`, `py` |
| JavaScript | `javascript`, `js` |
| TypeScript | `typescript`, `ts` |
| HTML | `html` |
| CSS | `css` |
| JSON | `json` |
| YAML | `yaml`, `yml` |
| Markdown | `markdown`, `md` |
| Bash / Shell | `bash`, `sh`, `shell` |
| PowerShell | `powershell`, `ps` |
| SQL | `sql` |
| Diff | `diff` |
| 纯文本 | `text` 或不指定 |

### 8.5 缩进代码块

每行前加**四个空格或一个制表符**。

```markdown
    这是缩进代码块
    它不支持语法高亮
```

> 围栏代码块更灵活（支持语法高亮），推荐优先使用围栏代码块。

### 8.6 在列表中使用代码块

````markdown
1. 打开文件

   ```cpp
   ifstream fin("input.txt");
   ```

2. 读取数据
````

> 代码块需要缩进对齐列表项的文字。

## 9. 表格

### 9.1 基本语法

```markdown
| 列标题1 | 列标题2 | 列标题3 |
| ------- | ------- | ------- |
| 数据A   | 数据B   | 数据C   |
| 数据D   | 数据E   | 数据F   |
```

### 9.2 对齐方式

在分隔行中使用冒号控制对齐：

```markdown
| 左对齐 | 居中对齐 | 右对齐 |
| :---   | :---:    | ---:   |
| A      | B        | C      |
```

- `:---` — 左对齐
- `:---:` — 居中对齐
- `---:` — 右对齐
- `---` — 默认左对齐

### 9.3 表格中的特殊字符

需要在表格中显示 `|` 时，使用 `\|` 转义。

### 9.4 表格中的代码和样式

```markdown
| 函数名 | 返回值 | 复杂度 |
| --- | --- | --- |
| `sort()` | `void` | **O(n log n)** |
| `find()` | `iterator` | *O(n)* |
```

### 注意事项

- 表格前后建议加空行，某些解析器需要空行来正确识别表格
- 管道符 `|` 两边的空格**不是必需的**，但加入空格可以提高源码可读性
- 分隔行中的 `-` 数量至少为 3 个，一般对齐数据宽度即可

## 10. 引用块

### 10.1 基础语法

```markdown
> 这是一条引用。
```

### 10.2 多行引用

```markdown
> 第一行引用。
>
> 第二行引用（中间加入 > 可以保持连续）。
```

### 10.3 嵌套引用

```markdown
> 一级
>> 二级
>>> 三级
```

### 10.4 引用中包含其他元素

```markdown
> # 标题也可以放在引用中
>
> - 列表
> - 也可以
>
> ```cpp
> cout << "还有代码";
> ```
```

### 注意事项

- `>` 和内容之间建议加空格，保持可读性
- 引用块可以嵌套其他任何 Markdown 元素

## 11. 分割线

### 语法

单独一行使用三个以上的 `***`、`---` 或 `___`。

```markdown
---
***
___
```

### 注意事项

- 使用 `---` 时前后必须有空行，否则会被误解析为二级标题（Setext 风格）
- 符号之间可以有空格（如 `* * *`），但不影响渲染
- 建议统一使用 `---`，简洁且通用

## 12. 任务列表

### 语法

```markdown
- [ ] 未完成的任务
- [x] 已完成的任务
```

**效果：**
- [ ] 未完成的任务
- [x] 已完成的任务

### 嵌套任务列表

```markdown
- [ ] 大任务
  - [x] 子任务 A
  - [ ] 子任务 B
```

### 注意事项

- 方括号内 `[ ]` 是空格表示未完成，`[x]` 或 `[X]` 表示完成
- 这是 GitHub Flavored Markdown (GFM) 扩展，不是标准 Markdown
- 在 GitHub Issues / PR 中使用效果最佳

## 13. 脚注

### 语法

```markdown
这里是一段文字[^1]，这里引用另一个来源[^note]。

[^1]: 这是第一个脚注的内容。
[^note]: 这是第二个脚注，可以写多段内容。
```

### 注意事项

- 脚注标记可以是数字或文字，但建议使用有意义的标识符
- 脚注内容可以放在文档的任何位置，通常放在末尾
- 脚注是扩展语法，GitHub、Typora、Obsidian 支持，部分平台不支持
- 在 GitHub 上脚注会渲染到页面底部

## 14. 数学公式（LaTeX）

### 14.1 行内公式

使用单个 `$` 包裹：

```markdown
欧拉公式：$e^{i\pi} + 1 = 0$
```

**效果**：$e^{i\pi} + 1 = 0$

### 14.2 块级公式

使用两个 `$$` 包裹：

```markdown
$$
\sum_{i=1}^{n} i = \frac{n(n+1)}{2}
$$
```

**效果**：

$$
\sum_{i=1}^{n} i = \frac{n(n+1)}{2}
$$

### 14.3 常用 LaTeX 语法速查

| 语法 | 效果 | 说明 |
| --- | --- | --- |
| `x^2` | $x^2$ | 上标 |
| `x_i` | $x_i$ | 下标 |
| `\frac{a}{b}` | $\frac{a}{b}$ | 分数 |
| `\sqrt{x}` | $\sqrt{x}$ | 平方根 |
| `\sqrt[n]{x}` | $\sqrt[n]{x}$ | n 次方根 |
| `\sum_{i=1}^{n}` | $\sum_{i=1}^{n}$ | 求和 |
| `\prod_{i=1}^{n}` | $\prod_{i=1}^{n}$ | 连乘 |
| `\int_{a}^{b}` | $\int_{a}^{b}$ | 积分 |
| `\lim_{x \to \infty}` | $\lim_{x \to \infty}$ | 极限 |
| `\infty` | $\infty$ | 无穷大 |
| `\log` `\ln` | $\log$ $\ln$ | 对数 |
| `\sin` `\cos` `\tan` | $\sin$ $\cos$ $\tan$ | 三角函数 |
| `\max` `\min` | $\max$ $\min$ | 最大/最小值 |
| `\alpha \beta \gamma` | $\alpha \beta \gamma$ | 希腊字母 |
| `\pi \theta \lambda` | $\pi \theta \lambda$ | 常用希腊字母 |
| `\cdot \times \div` | $\cdot \times \div$ | 乘除符号 |
| `\pm \mp` | $\pm \mp$ | 正负号 |
| `\leq \geq` | $\leq \geq$ | 不等号 |
| `\neq` | $\neq$ | 不等于 |
| `\approx` | $\approx$ | 约等于 |
| `\Rightarrow` | $\Rightarrow$ | 推导箭头 |
| `\mathbb{R}` | $\mathbb{R}$ | 实数集 |
| `\mathcal{O}` | $\mathcal{O}$ | 大 O 表示法 |
| `\text{中文}` | — | 公式中插入中文 |

### 14.4 矩阵

```markdown
$$
\begin{bmatrix}
1 & 2 & 3 \\
4 & 5 & 6 \\
7 & 8 & 9
\end{bmatrix}
$$
```

### 14.5 分段函数（cases）

```markdown
$$
f(n) =
\begin{cases}
n/2, & n \text{ 为偶数} \\
3n+1, & n \text{ 为奇数}
\end{cases}
$$
```

### 注意事项

- 数学公式渲染需要 MathJax 或 KaTeX 支持（GitHub 原生不支持 `$$`，但 VS Code + 插件、Typora 等支持）
- GitHub 上建议使用 [codecogs](https://latex.codecogs.com/) 等在线服务生成公式图片作为替代

## 15. HTML 嵌入

Markdown 支持直接嵌入 HTML 标签，用于实现原生语法无法覆盖的效果。

### 15.1 折叠面板

```html
<details>
<summary><b>点击展开</b></summary>

这里是被折叠的内容。
支持 Markdown 语法和代码块。

</details>
```

### 15.2 键盘按键

```html
<kbd>Ctrl</kbd> + <kbd>C</kbd>
```

### 15.3 文本对齐

```html
<p align="center">居中文字</p>
<p align="right">右对齐文字</p>
```

### 15.4 下划线与删除线增强

```html
<u>下划线文字</u>
<s>另一种删除线</s>
<mark>高亮标记</mark>
```

### 15.5 强制换行

```html
第一行<br>第二行
```

### 15.6 注释

```html
<!-- 这是 HTML 注释，不会渲染 -->
```

### 注意事项

- 不是所有 HTML 标签都会被 Markdown 渲染器支持（安全限制）
- HTML 块级标签（`<div>`、`<table>` 等）前后的空行很重要
- 在 HTML 标签内部的 Markdown 语法**不会被解析**

- 可以直接使用 Unicode emoji：直接粘贴 😄 🚀 ✅
- Unicode emoji 的兼容性更好，推荐直接使用

## 17. 转义字符

当文字中包含与 Markdown 语法冲突的字符时，需要用反斜杠 `\` 转义。

### 可转义字符列表

| 字符 | 转义写法 | 场景 |
| --- | --- | --- |
| `\` | `\\` | 反斜杠自身 |
| `` ` `` | `` \` `` | 反引号 |
| `*` | `\*` | 星号 |
| `_` | `\_` | 下划线 |
| `#` | `\#` | 井号 |
| `+` | `\+` | 加号 |
| `-` | `\-` | 减号 |
| `.` | `\.` | 句点（有序列表） |
| `!` | `\!` | 感叹号 |
| `{` `}` | `\{` `\}` | 大括号 |
| `[` `]` | `\[` `\]` | 方括号 |
| `(` `)` | `\(` `\)` | 小括号 |
| `<` | `\<` | 小于号 |
| `>` | `\>` | 大于号 |
| `|` | `\|` | 管道符（表格中） |
| `~` | `\~` | 波浪线 |

### 示例

```markdown
这个 \*星号\* 不会被解析为斜体。
C++ 模板：`vector\<int\>`
方法一 \| 方法二
```

### 注意事项

- 在代码块和行内代码中**不需要**转义，代码内的内容不会被当作 Markdown 解析
- 在 URL 中通常不需要转义

## 18. 目录与锚点

### 18.1 手动创建目录

```markdown
- [1. 标题](#1-标题)
- [2. 文本样式](#2-文本样式)
  - [2.1 加粗](#21-加粗)
```

### 18.2 锚点 ID 规则

不同平台生成锚点 ID 的规则略有不同：

| 平台 | 规则 | 示例 |
| --- | --- | --- |
| GitHub | 小写 + 空格变 `-` + 去掉标点 + 中文保留 | `#1-标题` |
| Typora | 与标题文字一致（含中文） | `#1-标题` |
| GitLab | 小写 + 空格变 `-` + 去掉标点 | `#1-` |

### 18.3 自动生成目录

部分编辑器和工具支持自动生成 TOC（Table of Contents）：

- **VS Code**：安装 `Markdown All in One` 插件，使用命令 `Create Table of Contents`
- **Typora**：`段落 → 内容目录` 自动插入
- **Obsidian**：`核心插件 → 大纲`

## 19. 定义列表与缩写

### 19.1 定义列表

定义列表不是标准 Markdown 语法，需要用 HTML 实现：

```html
<dl>
  <dt>名词</dt>
  <dd>名词的解释或定义。</dd>

  <dt>另一个名词</dt>
  <dd>对应的定义。</dd>
</dl>
```

### 19.2 缩写

```html
<abbr title="HyperText Markup Language">HTML</abbr>
```

**效果**：鼠标悬停在 HTML 上会显示 "HyperText Markup Language"。

### 注意事项

- 部分 Markdown 引擎（如 Pandoc、kramdown）支持原生定义列表语法，但 GitHub Flavored Markdown 不支持
- 在 GitHub 上请使用 HTML 标签实现

## 20. 常用技巧与最佳实践

### 20.1 文档结构规范

```markdown
# 文档标题

> 文档说明 / 简介

---

## 📑 目录

- [一级章节](#)
  - [二级小节](#)

---

## 1. 一级章节

### 1.1 二级小节

内容...

---

> **📝 总结 / 参考**
```

### 20.2 排版建议

| 建议 | 说明 |
| --- | --- |
| 标题使用 `#` 而非 `===` | 风格统一，更易阅读 |
| 标题前后留空行 | 提高源码可读性，避免渲染问题 |
| 列表标记统一使用 `-` | 避免混用 `-` `*` `+` |
| 表格管道符对齐 | 虽然不影响渲染，但利于源码维护 |
| 代码块指定语言 | 获得语法高亮 |
| 链接使用有意义的文字 | 避免 "点击这里"，改用描述性文字 |
| 适度使用 emoji | 增强可读性，但不要过度 |

### 20.3 避免混淆的场景

```markdown
<!-- ❌ 错误：--- 容易被误认为二级标题 -->
这是我的内容
---
继续写...

<!-- ✅ 正确：空行后使用分割线 -->
这是我的内容

---

继续写...
```

### 20.4 空行的重要性

以下情况建议在前后加空行：

- 标题前后
- 表格前后
- 代码块前后
- 列表前后
- 分割线前后
- 引用块前后

## 21. 不同平台的差异

Markdown 没有统一的官方标准，不同平台有各自的扩展和差异。

### 主要变体

| 变体 | 主要使用场景 | 额外支持 |
| --- | --- | --- |
| **CommonMark** | 标准化规范 | 基础语法 |
| **GitHub Flavored Markdown (GFM)** | GitHub | 任务列表、表格、删除线、自动链接 |
| **GitLab Flavored Markdown (GLFM)** | GitLab | 类似 GFM + 更多扩展 |
| **Typora** | 本地编辑器 | 高亮、上下标、图表、TOC |
| **Obsidian** | 知识管理 | 双向链接、Callout、标签 |
| **MDX** | React 文档 | JSX 组件嵌入 |

### 常见兼容性问题及解决方案

| 功能 | 是否通用 | 替代方案 |
| --- | --- | --- |
| 表格 | ✅ GFM 通用 | 无需替代 |
| 任务列表 | ✅ GFM 通用 | 无需替代 |
| 代码块语法高亮 | ✅ 通用 | 无需替代 |
| 数学公式（`$$`） | ⚠️ 需渲染器 | 嵌入公式图片 |
| 高亮（`==`） | ⚠️ 非标准 | `<mark>` 标签 |
| 上下标（`~` `^`） | ⚠️ 非标准 | `<sub>` `<sup>` 标签 |
| 脚注 | ⚠️ 非标准 | 手动编号 + 链接 |
| TOC 自动生成 | ⚠️ 非标准 | 手动编写目录 |
| Flowchart / 流程图 | ⚠️ 非标准 | 使用图片 |
| Mermaid 图表 | ⚠️ GitHub 支持 | 使用图片或外部工具 |

### 平台特性速查

**GitHub** — ✅ 最广泛支持 GFM：任务列表、表格、脚注、emoji、Mermaid、折叠面板、数学公式（MathJax）

**VS Code** — ✅ 基本 GFM 支持，通过插件可扩展（Markdown All in One、Markdown Preview Enhanced）

**Typora** — ✅ WYSIWYG 编辑体验，支持高亮、图表、数学公式、TOC 自动生成

**Obsidian** — ✅ 双向链接 `[[]]`、Callout 块、标签系统

**Notion** — ✅ 所见即所得编辑器，支持数据库、嵌入块，但 Markdown 导入/导出不完全兼容
